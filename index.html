한 줄 요약

졸업작품을 준비하는 공대생과 그 결과물을 평가하는 검토자를 위해, 기획(PRD)·구현·검증·AI 협업 근거를 한 사이트에서 확인하게 해 주는 브랜딩 포트폴리오.

① 왜? — 해결하려는 문제
세부 문제 1 · 근거가 흩어진다

상황 예시: 사진은 있는데 회로도·STL·코드가 폴더마다 흩어져 있다.

세부 문제 2 · 주장과 근거가 구분되지 않는다

상황 예시: “직접 만든 거 맞아요?”라는 질문에 답할 자료가 없다.

세부 문제 3 · AI 협업이 불투명하다

상황 예시: AI가 만든 부분과 내가 검증한 부분이 구분되지 않는다.

문제 문장: 졸업작품을 준비하는 공대생은 구현 결과물의 기획·검증·AI 협업 근거를 한곳에서 보여줄 기준이 없어서, 평가자에게 “직접 만들고 검증했다”는 사실을 증명하기 어렵다.

② 누구를 위해? — 페르소나 2명 (가상 인물)
주 사용자 · 이서준 (가명)

“만들긴 했는데, 이걸 어떻게 증명하지?”

나이·학력·직업
25세 · 전기전자공학과 4학년 · 졸업작품 준비 중
상황
회로·3D 출력물·웹 대시보드를 만들었지만 기획·검증 기록이 흩어져 있다.
관심사
취업 포트폴리오, 하드웨어와 소프트웨어를 함께 다루는 직무
원하는 것
내 결과물이 실제로 구현·검증됐음을 한 번에 보여주고 싶다.
해결하고 싶은 것
“어디까지 직접 했나요?”라는 질문에 바로 근거를 보여주고 싶다.
또 다른 사용자 · 최 교수 (가명, 검토자)

“말이 아니라 근거를 짧게 보고 싶다.”

직업

상황
여러 팀의 포트폴리오를 팀당 몇 분 안에 훑어봐야 한다.
원하는 것
전공·강점·근거 위치를 빠르게 파악하고 싶다.
해결하고 싶은 것
직접 구현·검증했는지를 짧은 시간에 판단하고 싶다.
사용자 시나리오
  1. 이서준이 면접·심사용으로 포트폴리오 링크를 보낸다.
  2. 검토자가 링크를 열어 첫 화면에서 5초 안에 전공·강점을 파악한다.
  3. 프로젝트 카드에서 PRD 모달을 열어 숫자 성공 기준을 확인한다.
  4. AI 로그와 수정 이력으로 어디까지 직접 검증했는지 확인한다.
  5. 궁금한 점은 문의 메일 작성으로 바로 묻는다.
③ 무엇을? — 목표와 성공 기준
목표: 검토자가 10초 안에 “누가·무엇을·근거는 어디”를 확인한다
1. 정체성이 바로 보인다측정 전

첫 화면을 5초 본 지인 3명 중 3명이 전공·강점·다음 행동을 말한다

확인 방법 · 5초 보여 준 뒤 화면을 가리고 질문

2. 근거를 확인할 수 있다충족

프로젝트 3개 모두에 PRD·AI 로그 모달이 있고, 숫자 성공 기준이 1개 이상 적혀 있다

확인 방법 · 카드의 버튼 6개를 눌러 내용 확인

3. 어디서나 깨지지 않는다측정 전

375·768·1280px에서 레이아웃 깨짐 0건

확인 방법 · 크롬 개발자도구 기기 모드로 3개 폭 확인

4. 모든 버튼이 작동한다측정 전

메뉴·모달 6종·탭 7종·툴박스 3종·문의 메일 작성이 100% 동작한다

확인 방법 · 체크리스트를 만들어 하나씩 클릭

5. 툴박스 계산이 맞다측정 전

RC 계산기에 10kΩ·100nF을 넣으면 fc ≈ 159Hz가 나오고, 시뮬레이터 기본 설정에서 필터 적용 전환 횟수가 필터 없음 이하다

확인 방법 · 손계산 값과 비교, 노이즈 5회 새로 생성해 확인

6. 쉽게 문의한다측정 전

문의하기를 누른 뒤 3번 이내 조작으로 메일 작성 창이 열린다

확인 방법 · 직접 따라 해 보며 횟수 세기

‘측정 전’은 아직 직접 확인하지 않은 기준입니다. 확인하면 결과를 적어 ‘충족’ 또는 ‘미달’로 바꿉니다.

④ 어떤 기능? — “나는 [누구]로서, [무엇]을 하고 싶다”
F1Must · 화면 1

나는 검토자로서, 첫 화면에서 전공·강점·다음 행동을 5초 안에 파악하고 싶다.

완료 기준 · 첫 화면에 선언문과 ‘프로젝트 보기’ 버튼이 함께 있다

F2Should · 화면 1

나는 졸업작품 준비생으로서, 제공 서비스와 제외 범위를 확인하고 싶다.

완료 기준 · 3단계 솔루션과 제외 범위 문구가 표시된다

F3Must · 화면 2

나는 검토자로서, 프로젝트별 PRD와 성공 기준을 열어 보고 싶다.

완료 기준 · 프로젝트마다 문제·성공 기준·범위 외 3칸이 든 모달이 열린다

F4Must · 화면 2

나는 검토자로서, AI 프롬프트와 수정 이력을 확인하고 싶다.

완료 기준 · 프로젝트마다 AI 로그 모달에 프롬프트가 1개 이상 표시된다

F5Should · 화면 2

나는 준비생으로서, RC 계산·필터 시뮬레이션·PRD 생성 도구를 써 보고 싶다.

완료 기준 · 3개 도구가 입력에 즉시 반응하고 결과가 화면에 나온다

F6Must · 화면 3

나는 의뢰자로서, 메일 작성이나 링크 복사로 바로 문의하고 싶다.

완료 기준 · 메일 작성 창이 열리고, 실패하면 안내 문구가 나온다

수정 조치 및 근거: 6항목 PRD 탭을 신설하고, 직접 확인하지 않은 성공 기준은 ‘측정 전’으로 표기.

[수정 이력 #7] 타깃·문제 중복 정리 및 PRD 강화 명세 항목: PRD 형식

수정 조치 및 근거: 서비스 섹션의 중복 블록을 제거해 PRD 탭으로 단일화하고, 상황 예시·시나리오·확인 방법·완료 기준을 추가.

프로젝트 성찰 일지: AI 협업과 융합형 메이커로의 진로 확장

김현수 · 전기전자공학 전공

1. 역할 나누기 (사람의 기획·검증 vs AI의 구현)

전기전자공학 전공과 3D 모델링 경험을 바탕으로 브랜드 핵심 가치(‘실현과 꼼꼼함’), 타깃 고객 정의, PRD의 정량 성공 기준 및 제외 범위 설정은 직접 설계했습니다. AI에게는 설계된 명세서에 맞춘 HTML/Tailwind UI 초안 생성과 반응형 레이아웃 구조화를 맡기고, 결과물의 코드 무결성과 정적 배포 검증은 직접 수행했습니다.

2. 검증과 수정 (명세서와 달랐던 부분 바로잡기)

초기 AI 생성물에서는 상세 모달 스크립트가 누락되고 연락처가 `example.com` 임시 값으로 채워져 있었습니다. 사전 작성한 화면 설계서와 대조하여 모든 버튼이 실제로 작동하도록 모달 데이터와 자바스크립트 로직을 보완했고, 근거가 없는 수치는 삭제해 기획의 제외 범위에 맞췄습니다.

3. AI의 한계와 주의할 점

AI는 시각적으로 그럴듯한 코드를 빠르게 만들어 주지만, 코드 일부가 생략되거나 실제 배포 환경(Netlify 경로 및 빌드 설정)의 오류를 스스로 검증하지 못하는 한계가 있었습니다. 결과물에 대한 최종 책임을 지기 위해서는 반드시 명세서 체크리스트와 실제 브라우저·외부 접속 테스트를 거쳐야 함을 확인했습니다.

4. 나의 진로 대안 및 향후 실행 계획

이번 MVP 제작을 통해 전기전자 하드웨어 지식에 3D 시제품 설계와 웹 구현 역량을 결합하면, 단순 엔지니어를 넘어 아이디어를 끝까지 시각화·검증하는 ‘융합형 메이커·기술 창직가’로 확장할 수 있음을 확인했습니다. 다음 단계로는 실제 공과계열 학우 및 메이커 3명 이상의 시제품·포트폴리오 제작 피드백을 받아 고객 검증 근거를 더욱 고도화할 계획입니다.

RC 저역통과 필터

센서 신호의 고주파 노이즈를 거르는 1차 RC 필터의 차단주파수를 계산하고, 목표 fc에 맞는 표준 저항값(E-series)을 추천합니다.

fc = 1 / (2π·R·C)  |  τ = R·C

※ 이상적인 소자 기준 값입니다. 실제 회로에서는 소자 오차·ADC 입력 임피던스·센서 출력 저항이 fc를 바꾸므로 측정으로 확인하세요.

노이즈 필터링 시뮬레이터

가상의 센서값(ADC 0~1023)에 노이즈·스파이크를 더한 뒤, 이동평균과 히스테리시스 임계값이 오트리거를 얼마나 줄이는지 확인합니다. 실제 장비 측정값이 아닌 시뮬레이션 데이터입니다.
